# Object Lock in S3

Object Lock S3 ka ek feature hai, jisme hum S3 ke kisi object par lock laga dete hain jisse koi bhi user us object ko delete ya overwrite nhi kar payega.

Object ka matlab S3 bucket ke ander stored data.

S3 Object Lock ka purpose kisi object version ko ek specified retention period ke dauran delete ya overwrite hone se protect karna hai.

Agar simple words mein kahein: Ek baar agar aapne koi file S3 Object Lock ke sath bucket mein daal di, toh uske baad ek nirdharit samay (fixed time) tak use duniya ka koi bhi taqat delete ya overwrite nahi kar sakti—na hi aapka koi senior developer, na hi company ka admin, aur yahan tak ki khud AWS ke Root account ke paas bhi use mitane ki permission nahi hoti.

Amazon S3 Object Lock ek data-protection feature hai jo S3 objects ko immutable banane mein help karta hai, yani specified retention period ya legal hold ke dauran object version ko delete ya overwrite hone se protect kiya ja sakta hai.

Yeh feature ransomware attacks se bachne aur banking/healthcare ke strict compliance regulations (jaise SEC Rule 17a-4) ko poora karne ke liye banaya gaya hai.

<br>

### Object Lock ki zarurat kyu padti hai?

Maan lo company ka production database har raat S3 mein backup hota hai:
```
s3://prod-backups/

├── backup-01.sql
├── backup-02.sql
├── backup-03.sql
└── backup-04.sql
```

Company ki requirement hai:
- "Har backup ko kam se kam 1 saal tak delete nahi kiya ja sakta."

Ab suppose kisi attacker ne AWS credentials compromise kar liye. Attacker ke paas S3 permissions hain.

Agar normal bucket hai:
```
Attacker
   │
   ▼
Delete backup
   │
   ▼
Backup deleted
```
Normal bucket mein kisi object ko delete karoge to vo delete ho jayega. To object ke purane versions bhi available rahe isliye bucket mein versioning on karte hain jisse ek object ke purane versions bhi safe rahe.

Lekin agar bucket mein versioning on hai, agar attacker purane versions ko delete kare to bhi vo object ke versions ko delete kar sakte hai.

Kyunki versioned bucket mein normal delete generally delete marker create karta hai aur previous versions preserve rehte hain. Lekin authorized identity agar particular versions ko permanently delete karne ki permission rakhti hai, to Versioning alone complete protection nahi deta. Matlab agar attacket ke paas ese credentials aa gaye jisme versions ko delete karne ki permission hai to attacker object ke versions ko delete kar sakta hai.

To kisi attacker ke paas object delete karne ki permission hai, agar fir bhi vo objects ke versions ko delete na kar paye, isi reason ke wajah se object lock use kiya jata hai.

Object lock yahan ye security deta hai ki koi bhi user object versions ko ek particular time tak delete ya modify nahi kar sakta chahe user ke paas object version delete karne ki permission hi kyu na ho.

### Prerequisites 

S3 Object Lock ko use karne ke liye kuch zaroori baatein jaan na zaroori hai:
- **Versioning Mandate**: Object Lock sirf aur sirf un buckets par kaam karta hai jahan Versioning ON (Enabled) hoti hai. Agar versioning nahi hai, to Object Lock lag hi nahi sakta.
- **Creation Time Option**: Jab aap naya bucket banate hain, tabhi aapko Object Lock ka option turn-on karna padta hai. Agar bucket pehle se bana hua hai aur usme data hai, to aap direct console se ise chalu nahi kar sakte; uske liye AWS Support se baat karni padti hai ya special setup lagta hai.

### WORM ka kya meaning hai?

Object Lock ka core concept **WORM** hai: **Write Once, Read Many**.

Iska simple idea hai ki data ko ek baar write karne ke baad defined protection period mein us data ko delete ya modify nahi kiya ja sake.

Real-world analogy ke liye ek legal archive imagine karo. Company ne ek regulatory document archive mein deposit kiya aur policy hai ki us document ko 7 saal tak remove nahi kiya ja sakta.

S3 Object Lock isi tarah ka storage-level retention behavior provide kar sakta hai.

Conceptually:
```
Write
  ↓
Protected Version
  ↓
Read
Read
Read
Read

Delete ✗
Overwrite ✗
```
Retention protection active rehne tak.

### Object Lock ka main use case: Compliance

Object Lock ka major use case hai regulatory/compliance requirements jahan records ko ek specific period tak immutable rakhna required hota hai.

Examples:
- Financial records.
- Audit records.
- Transaction records.
- Regulatory data.
- Security logs.
- Backup archives.
- Evidence data.

Maan lo company ko requirement hai:
- "Financial transaction records ko 7 years tak delete nahi kiya ja sakta."

Object Lock ke retention mechanism ke through aisi requirement implement ki ja sakti hai.

Conceptually:
```
Transaction Record
       │
       ▼
S3
       │
       ▼
Object Lock
       │
       ▼
7-Year Retention
       │

Cannot be deleted during retention
```

AWS Object Lock ko regulatory compliance aur data-retention scenarios ke liye specifically support karta hai.

### Object Lock ke do major protection mechanisms

S3 Object Lock mein primarily do important concepts hain:
- Retention Period.
- Legal Hold.

Retention Period ke andar do modes hote hain:
- Governance Mode.
- Compliance Mode.


Isliye complete structure:
```
Object Lock
     |
     ├── Retention
     │     |
     │     ├── Governance Mode
     │     |
     │     └── Compliance Mode
     │
     └── Legal Hold
```

<br>

**Retention Period**:

Retention Period ka matlab hai Object version ko ek specific date/time tak protected rakhna.

Example:
```
Object:
database-backup-01.sql

Retention:
30 days
```

Agar object 02 September ko create hua:
```
02 Sep
   ↓
Object created

30-day retention

   ↓

02 Oct
   ↓
Retention expires
```
02 October tak object protected rahega.

Object Lock lagate waqt aapko batana padta hai ki file ko kitne samay tak lock rakhna hai. Ise hum Retention Period kehte hain.
- Aap ise Days (Din) ya Years (Saal) mein set karte hain (Jaise: 30 din ya 5 saal).
- Jab aap koi file upload karte hain, to S3 usme ek metadata timestamp jod deta hai jise ```Retain Until Date``` kehte hain.
- Example: Agar aapne 1 January 2026 ko 5 din ke retention period ke sath file upload ki, to uski Retain Until Date ho jayegi 6 January 2026. Is tarikh ke aane tak file poori tarah se un-deletable rahegi. Tarikh nikalne ke baad file normal ho jayegi aur use delete kiya ja sakega.

Retention period ke ander 2 modes hote hain:
- Governance Mode.
- Compliance Mode.

<br>

**Governance Mode**:

Governance Mode ka purpose ye hai ki normal users/admins object ko delete ya retention ko modify na kar saken. Lekin highly privileged users, agar unke paas required permissions hain, governance controls ko bypass kar sakte hain.

Example:

Maan lo company ka internal backup system hai. Company chahti hai:
- "Developers accidentally backups delete na kar saken."

Lekin security administrators ko emergency mein special approval process ke through retention bypass karne ki ability chahiye.

Yeh thoda flexible mode hota hai. Isme aam users ya hackers aapke data ko delete nahi kar sakte, lekin agar kisi user ke paas ek special AWS permission ho (```s3:BypassGovernanceRetention```), to wo lock ko bypass karke file delete kar sakta hai.

Yeh testing ke liye ya internal company rules ke liye hota hai jahan aap chahte hain ki galti se koi delete na kare, lekin kisi emergency mein IAM Admin ke paas file delete karne ka power ho.

<br>

**Compliance Mode**:

Compliance Mode ka purpose much stricter immutability provide karna hai.

Is mode mein protected object version ko retention period ke andar delete karna ya retention period ko shorten karna normally possible nahi hota, including for users with highly privileged administrative permissions.

Yeh sabse strong aur strict mode hai. Ek baar agar aapne kisi file ko Compliance Mode mein lock kar diya, to duniya ki koi taqat us file ko retention period khatam hone se pehle delete nahi kar sakti.
- Yahan tak ki aapka AWS Root Account, IAM Admin, ya khud AWS ki technical support team bhi us file ko delete nahi kar sakti.
- Is mode mein aap lock ka samay (retention period) badha to sakte hain (jaise 5 saal se 7 saal kar sakte hain), lekin use kam nahi kar sakte (5 saal se 3 saal nahi kar sakte) aur na hi lock ko band kar sakte hain.

<br>
<br>

**Legel Hold**:

Legal Hold retention period se different concept hai.

Retention Period: "Data ko X date tak protect karo."

Legal Hold: "Is object ko tab tak protected rakho jab tak legal hold remove na ho."

Yaani Legal Hold ke saath predefined expiry date zaruri nahi hoti.

Maan lijiye aapki company par koi court case ya audit chal raha hai, aur aapko nahi pata ki yeh case kab tak chalega (1 mahina ya 10 saal). Aise scenario ke liye AWS deta hai Legal Hold.
- Kaise kaam karta hai? Legal Hold mein koi Retain Until Date (expiry date) nahi hoti. Yeh ek ON/OFF switch ki tarah hota hai.
- Jab tak Legal Hold ON hai, file delete nahi ho sakti. Jab court case khatam ho jaye, to jis user ke paas ```s3:PutObjectLegalHold``` permission hai, wo ise OFF kar dega, aur uske baad file delete ki ja sakegi.
- Governance/Compliance ke sath combination: Aap Legal Hold ko standard retention period ke sath bhi laga sakte hain.

<br>
<br>

### Compliance Mode dangerous bhi ho sakta hai

Agar tumne galti se:
```
Compliance Mode
+
Retention = 10 years
```
configure kar diya.

To tum expected retention period se pehle object ko delete ya retention shorten nahi kar paoge.

Isliye Compliance Mode use karne se pehle:
- Retention requirements verify karo.
- Legal/compliance requirements verify karo.
- Data lifecycle samjho.
- Storage cost calculate karo.
- Recovery procedure test karo.

Kyunki Compliance Mode intentionally difficult-to-bypass protection provide karta hai.

### Real-World Scenario: Ransomware Attack Se Suraksha

Maan lijiye ek hacker aapke AWS infrastructure mein ghus gaya. Usne aapka saara original data encrypt kar diya ya delete karne ki koshish ki taaki woh aap se ransom (bhadta/paisa) mang sake.

**Agar Compliance Mode ON hai**: Hacker chahe kitna bhi bada genius ho, jab woh aapki files par DeleteObject chalayega, toh AWS use Access Denied ka error de dega. Hacker aapke data ko nuksan nahi pahuncha payega kyunki S3 ki hard drive ka software core level par us request ko block kar dega. Aapka backup hamesha safe rahega.

### Object lock ko bucket par lagaya jata hai ya object level par

S3 Object Lock bucket level aur object level dono par kaam karta hai.

**Bucket Level vs Object Level (Dono mein kya farq hai?)**:

**Bucket Level (Default Settings)**: Jab aap poore bucket par Object Lock lagate hain, to aap ek "Default Retention Policy" set kar dete hain (Jaise: Compliance Mode, 30 days). Iska matlab yeh hota hai ki ab is bucket mein jo bhi nayi file upload hogi, us par apne aap 30 din ka lock lag jayega. Aapko har ek file ke liye alag se batane ki zaroorat nahi padegi.
- Jab tak aap bucket banate waqt ya uski settings mein ja kar Object Lock feature ko ON nahi karenge, tab tak aap kisi bhi single file ko lock nahi kar payenge.
- Bucket par S3 Versioning ka ON hona compulsory hai.
- Ek baar agar bucket par Object Lock ON ho gaya, toh use fir kabhi bhi OFF (Disable) nahi kiya ja sakta.


**Object Level (Specific Settings)**: Aap kisi ek specific file (object) par bhi lock lagate hain. Agar bucket par pehle se koi default policy set hai, tab bhi aap upload karte waqt kisi specific file ke liye us policy ko override kar sakte hain (jaise bucket ka default 30 din hai, par aapne kisi bohot important file par 5 saal ka lock laga diya). Ya fir aap pehle se upload ki gayi file par Legal Hold lagane ke liye object level ka use karte hain.
- Agar aap bucket level par koi automatic rule nahi lagate, toh aap har ek file ko uski ahemeyat (importance) ke hisab se alag-alag timeline par lock kar sakte hain. Jaise Bill_A ko 1 saal ke liye aur Bill_B ko 5 saal ke liye

### S3 Object Lock Kaise Lagaya Jata Hai?

Object lock lagane ka process do hisson mein hota hai: Bucket level par enable karna (Prerequisite) aur fir Retention Rules set karna.

**A : Bucket Banate Waqt Object Lock Enable Karna**:

Aap kisi bhi purane ya chalte hue bucket par direct Object Lock chalu nahi kar sakte. Ise bucket banate waqt hi enable karna padta hai.
- AWS Console mein jaakar S3 search karein aur Create Bucket par click karein.
- Bucket ka naam aur region chuniye.
- Bucket Versioning wale section mein jaakar ise Enable karein (Kyunki bina versioning ke object lock kaam nahi karta).
- Neeche scroll karke Advanced settings par click karein.
- Wahan aapko Object Lock ka option dikhega, use Enable par toggle kar dein.
- Aakhir mein Create bucket par click kar dein. Ab aapka bucket Object Lock support karne ke liye taiyar hai.

Note: Agar aapke paas koi purana bucket hai jisme pehle se data hai aur aapko usme object lock chahiye, to aapko AWS Support ticket raise karna padta hai ya fir data ko ek naye Object Lock-enabled bucket mein migrate karna padta hai).

<br>

**B: Bucket Level Par Default Policy Lagana**:

Bucket banane ke baad, agar aap chahte hain ki aane wali har file par apne aap lock lag jaye:
- S3 Console mein apne bucket ke naam par click karein.
- Properties tab mein jayein.
- Neeche scroll karke Object Lock background/default retention section par jayein aur Edit par click karein.
- Default retention ko Enable karein.
- Apna pasandida mode chuniye: Governance ya Compliance.
- Retention period daaliye (Jaise Days mein 90 ya Years mein 2).
- Save changes par click karein. Ab is bucket mein upload hone wali har file auto-lock ho jayegi.

<br>
<br>

**Object Level Par Specific Lock Lagana (Via AWS CLI / API)**:

Agar aap bucket level par koi automatic rule nahi lagate, toh aap har ek file ko uski ahemeyat (importance) ke hisab se alag-alag timeline par lock kar sakte hain. Jaise Bill_A ko 1 saal ke liye aur Bill_B ko 5 saal ke liye.

Ise lagane ke do tarike hain:

**A: AWS Management Console (UI) Se**:
- Apne S3 bucket ke andar kisi bhi File (Object) ke naam par click karein.
- Uske Properties tab mein niche scroll karein, wahan aapko Object lock retention aur Object lock legal hold ka section dikhega.
- Edit par click karein.
- Agar time-bound lock lagana hai, toh Retention ko ON karke Governance ya Compliance mode chunein aur date/days enter karke save kar dein.
- Agar bina date ka infinite lock lagana hai, toh Legal Hold ko ON kar dein.

**B: AWS CLI (Command Line) Se**:

Jab aap file upload kar rahe hon, tabhi aap CLI terminal mein parameters dekar object level lock laga sakte hain:
```
aws s3api put-object \
    --bucket my-secure-bucket \
    --key sensitive-report.pdf \
    --body local-report.pdf \
    --object-lock-mode COMPLIANCE \
    --object-lock-retain-until-date "2027-12-31T23:59:59Z"
```
(Is command se sensitive-report.pdf par 31 December 2027 tak ke liye absolute Compliance Lock lag jayega).

### Sabse Zaroori Rule (Override Priority)

Hamesha yaad rakhein ki Object level ki settings hamesha Bucket level ke default rule ko override (supercede) kar deti hain.

Agar bucket ka default rule kehta hai ki har file ko 10 din ke liye lock karo, lekin aapne file upload karte waqt use 100 din ka lock de diya, toh AWS use 100 din ke liye hi lock rakhega.
