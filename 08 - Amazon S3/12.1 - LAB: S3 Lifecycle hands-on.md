# LAB: S3 Lifecycle Hands-on

S3 Lifecycle Policies (Lifecycle Management) ki ek complete production-level master lab karte hain.

Production environments mein data har roz badhta hai, aur agar hum saara data hamesha ke liye premium storage (S3 Standard) mein rakhenge, toh company ka bill out-of-control ho jayega. Lifecycle policies isi problem ko solve karti hain—yeh aapke data ko uski age (umr) ke hisab se automatic sasti storage classes mein shift karti hain ya delete karti hain.

Is lab mein hum real-world IT companies ke saare major scenarios aur rules ko ek sath seekhenge.

<br>

### Lab Objective & Scenarios

Hum apni ```meri-bucket-puneet``` ka use karenge aur ek aisi custom Lifecycle Policy design karenge jisme hum 3 bade production rules lagayenge:
- **Rule 1 (Current Objects Transition)**: Jo hamari latest files hain, unhe 30 din baad Standard-IA mein bhejenge aur 90 din baad Glacier Deep Archive mein.
- **Rule 2 (Noncurrent Objects Transition)**: Kyunki bucket mein Versioning ON hai, toh files ke purane (chhupay hue) versions ko storage space bachane ke liye jaldi sasta karenge (15 din mein Standard-IA aur 60 din mein Glacier).
- **Rule 3 (Data Expiration/Deletion)**: Jo log files ya temporary files hain, unhe 180 din baad cloud se permanently delete (expire) kar denge taaki bill zero ho jaye.

<br>

### Step 1: Bucket Ke Management Menu Mein Jayein

- **AWS Console** mein login karein, search bar mein **S3** search karke open karein.
- Apni bucket ```meri-bucket-puneet``` ke naam par click karke use open karein.
- Upar diye gaye tabs mein se **Management** tab par click karein.
- Pehla hi section dikhega: **Lifecycle rules**. Uske right side mein diye gaye Orange color ke Create lifecycle rule button par click karein.

<br>

### Step 2: Rule Ka Base Set Karein (Name & Scope)

- Lifecycle rule name: Yahan ek clear naam dalein, jaise: ```Production-Data-Optimization-Rule```.
- **Choose a rule scope**: Yahan do options hote hain:
  - Limit the scope using one or more filters: Isse aap kisi specific folder (prefix) ya tag par rule laga sakte hain (jaise sirf ```/logs``` folder par).
  - Apply to all objects in the bucket: Yeh poori bucket ke saare data par lagta hai.
- Hum is lab mein **Apply to all objects in the bucket** wale radio button par click karenge.
- Niche aane wale safety check-box "I acknowledge that this rule will apply to all objects in the bucket" par **tick laga dein**.

<br>

### Step 3: Actions Chunein (Kya-Kya Karna Hai?)

Niche aapko Lifecycle actions ki ek list dikhega jahan bohot saare check-boxes honge. Hum yahan apne scenarios ke hisab se 3 main actions par tick lagayenge:
- ☑️ Move current versions of objects between storage classes (Latest files ko sasta karne ke liye).
- ☑️ Move noncurrent versions of objects between storage classes (Purane chhupay hue versions ko sasta karne ke liye).
- ☑️ Expire current versions of objects (Data ko automatic delete karne ke liye).

<br>

### Step 4: Rule 1 Configure Karein (Current Versions Transition)

Jaise hi aapne actions tick kiye, niche unke forms khul jayenge. Pehla form hoga Transition current versions of objects.
- **Storage class transitions**: Dropdown kholkar **Standard-IA** chunein.
- **Days after object creation**: Yahan likhein 30. (Iska matlab, file upload hone ke exact ```30``` din baad automatic Standard-IA mein chali jayegi).
- Niche diye gaye **Add transition** button par dobara click karein.
- Is baar dropdown se Glacier Deep Archive chunein aur Days mein likhein ```90```.

<br>

### Step 5: Rule 2 Configure Karein (Noncurrent Versions Transition)

Ab thoda aur niche scroll karein, aapko **Transition noncurrent versions of objects** ka section dikhega (Yeh tabhi kaam karta hai jab bucket ki versioning ON ho).
- **Storage class transitions**: Dropdown se **Standard-IA** select karein.
- **Days after objects become noncurrent**: Yahan likhein ```15```. (Iska matlab jaise hi kisi file ka naya version upload hoga aur purana version background mein chhupega, uske 15 din baad wo Standard-IA mein chala jayega).
- Dobara **Add transition** par click karein.
- Is baar dropdown se Glacier Flexible Retrieval chunein aur Days mein likhein ```60```.

<br>

### Step 6: Rule 3 Configure Karein (Data Expiration / Permanent Delete)

Ab sabse aakhri section par scroll karein: **Expire current versions of objects**.

Days after object creation: Yahan likhein ```180```.
- Mechanics: Iska matlab file upload hone ke 180 din baad AWS use automatic delete kar dega.

Dhyan dene wali baat: Kyunki hamari versioning ON hai, toh 180 din baad file completely delete nahi hogi, balki latest file par ek Delete Marker lag jayega aur wo noncurrent ban jayegi. Agar aap use bilkul saaf karna chahte hain, toh niche ek aur option dikhega: Permanently delete noncurrent versions, aap wahan bhi days set kar sakte hain (e.g., 200 days).

<br>

### Step 7: Review Aur Create

- Page ke sabse niche scroll karein. Wahan AWS aapko ek bohot hi pyaara Timeline Diagram (Summary) dikhayega. Us timeline ko dekh kar check kar lein ki aapke 30, 90, 60, aur 180 din wale saare transitions sahi line mein hain ya nahi.
- Sab kuch sahi hone par Create rule button par click kar dein.

Boom! Success! Aapki production-level Lifecycle Policy completely live ho chuki hai. Ab aap so sakte hain, aur AWS aapke data ka bill har mahine apne aap kam karta rahega.
