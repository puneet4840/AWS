# LAB: Implementing S3 Bucket Policy

Chaliye, S3 Bucket Policy ki ek grand hands-on lab karte hain. Yeh lab thodi lambi aur bohot zyada important hogi kyunki isme hum real-world production level ke 3 bade scenarios ko ek hi Bucket Policy ke andar tackle karenge.

Bina kisi visual editor ke, is baar hum direct JSON code ka use karenge, kyunki industries mein hamesha bucket policies JSON mein hi deploy ki jaati hain.

<br>

### Lab Objective

Hamari ```meri-bucket-puneet``` par ek aisi Bucket Policy lagana jo yeh 3 kaam ek sath kare:
- **Scenario 1**: Pure internet ke liye ek specific folder ko public/open karna (Static assets ke liye).
- **Scenario 2**: Kisi specific IP Address (jaise aapke office ka network) ke alawa baaki sabke liye data download block karna.
- **Scenario 3**: Galti se bhi koi file delete na kar sake, use strict block (Deny) karna.

<br>
<br>

### Step 1: Apne Computer Ka IP Address Pata Karein

Kyunki hum Scenario 2 mein IP restriction lagane wale hain, toh pehle aapko apna khud ka Public IP pata hona chahiye taaki aap khud block na ho jayein.
- Browser mein ek naya tab kholein aur search karein: ```what is my ip```.
- Jo aapko IPv4 address dikhe (e.g., ```122.161.45.210```), use copy karke notepad mein rakh lijiye.

<br>
<br>

### Step 2: Bucket Ke "Public Access Block" Ko Hatayein

Kyunki hum is policy mein ek folder ko public karne wale hain, toh AWS ka master safety switch (Block Public Access) hume band karna padega, varna AWS error dega.
- AWS Console mein S3 dashboard par jayein aur apni bucket ```meri-bucket-puneet``` par click karein.
- Upar diye gaye tabs mein se **Permissions** tab par click karein.
- Pehla section dikhega: **Block public access (bucket settings)**. Uske right side mein **Edit** button par click karein.
- **Block all public access** ke aage se tick hata (uncheck) dein.
- Niche **Save changes** par click karein.
- Confirm karne ke liye ek pop-up aayega, usme confirm likhein aur **Confirm** daba dein.

<br>
<br>

### Step 3: Bucket Policy Menu Mein Jayein

- **Permissions** tab ke andar hi thoda niche scroll karein, aapko **Bucket policy** ka section dikhega.
- Wahan **Edit** button par click karein. Aapke samne ek bada sa black color ka text box (editor) khul jayega.

<br>
<br>

### Step 4: JSON Code Ko Samajhein Aur Paste Karein

Niche diye gaye JSON code ko dhyan se dekhein. Isko paste karne se pehle notepad mein le jaakar **apna bucket name** aur **apna IP address** badal lijiye.

```
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "Scenario1PublicImagesFolder",
            "Effect": "Allow",
            "Principal": "*",
            "Action": "s3:GetObject",
            "Resource": "arn:aws:s3:::meri-bucket-puneet/public-assets/*"
        },
        {
            "Sid": "Scenario2IPBasedRestriction",
            "Effect": "Deny",
            "Principal": "*",
            "Action": "s3:GetObject",
            "Resource": "arn:aws:s3:::meri-bucket-puneet/*",
            "Condition": {
                "NotIpAddress": {
                    "aws:SourceIp": "YOUR_IP_ADDRESS/32"
                }
            }
        },
        {
            "Sid": "Scenario3BlockDeleteForEveryone",
            "Effect": "Deny",
            "Principal": "*",
            "Action": [
                "s3:DeleteObject",
                "s3:DeleteObjectVersion"
            ],
            "Resource": "arn:aws:s3:::meri-bucket-puneet/*"
        }
    ]
}
```

**Is Policy Ka Ek-Ek Statement Bilkul Clear Samajh Lijiye**:

- **Statement 1 (Public Assets)**: ```Principal: "*"``` ka matlab hai duniya ka koi bhi insaan. Resource mein humne poori bucket nahi di, balki aage ```/public-assets/*``` likha hai. Iska matlab agar bucket mein ```public-assets``` naam ka folder hai, toh uski saari files bina password ke internet par koi bhi dekh sakta hai.

- **Statement 2 (IP Lock)**: Yeh sabse khatarnak aur zaroori rule hai. ```Effect: "Deny"``` lagaya hai aur Condition mein likha hai ```NotIpAddress```. Iska matlab agar request aapke bataye gaye IP (```YOUR_IP_ADDRESS/32```) se NAHI aa rahi hai, toh use direct Deny (Block) kar do. (Note: ```/32``` ka matlab hota hai sirf ek single IP).

- **Statement 3 (Anti-Delete Guard)**: Isme humne ```Effect: "Deny"``` lagaya hai aur action mein ```DeleteObject``` dala hai. Kyunki ```Principal: "*"``` hai, iska matlab ab account ka admin ya koi bhi employee is bucket se koi file delete nahi kar payega jab tak yeh policy hatai nahi jaati.

### Step 5: Live Test Kariye (Testing the Scenarios)

Ab hum check karenge ki hamare teeno rules sahi se kaam kar rahe hain ya nahi:
- **Test For Scenario 3 (Delete Lock Check)**: Bucket ke andar jaiye, apni dummy picture ko select kariye aur top right se **Delete** button dabakar delete karne ki koshish kariye. AWS aapko **Access Denied** ka error de dega. Aapka delete lock perfect kaam kar raha hai!
- **Test For Scenario 2 (IP Lock Check)**: Apne mobile ka WiFi band kariye aur use Mobile Data (4G/5G) par connect kariye (isse aapke mobile ka IP badal jayega). Ab mobile ke browser mein AWS console login karke is file ko download karne ki koshish kariye, AWS aapko Block kar dega kyunki aapka mobile IP allowed list mein nahi hai.
