# Multi-part Upload

AWS S3 mein Multi-part Upload ek aisa feature hai jo aapko badi files (large objects) ka data ek single piece mein upload karne ke bajaye, use chhote-chhote tukdon (parts) mein divide karke parallelly upload karne ki permission deta hai.

S3 Multipart Upload Amazon S3 ka ek aisa feature hai jo aapko badi files (large objects) ko chote-chote tukdon (parts) mein tod kar, ek sath parallelly upload karne ki permission deta hai.

Agar aapki file ka size 100 MB se bada hai, to AWS officially recommend karta hai ki aap Multi-part Upload ka use karein. Vaise S3 mein aap single operation se maximum 5 GB tak ki file hi upload kar sakte hain, lekin agar aapki file 5 GB se lekar 5 TB (Terabytes) tak badi hai, to aapke paas Multi-part Upload use karne ke alawa koi option nahi hota.

<br>
<br>

### Multipart Upload Kya Hai aur Kyu use karte hain?

Normal upload (Single Operation) mein jab aap S3 par koi file bhejte hain, toh poori file ek single stream mein jaati hai. Lekin Multipart Upload mein, S3 aapki ek badi file ko chhote-chhote tukdon (parts) mein tod deta hai aur unhe alag-alag (parallelly) upload karta hai.

Jab saare parts S3 ke paas pahunch jaate hain, toh S3 unhe aapas mein jodkar (assemble karke) phir se ek single original file bana deta hai.

**S3 ke Rules aur Limits**:
- **File Size Limit**: Aap ek single PUT request se max 5 GB tak ki file upload kar sakte hain. Agar file 5 GB se badi hai (S3 ki max object limit 5 TB hai), toh aapko Multipart Upload use karna hi padega.
- **Part Size Limit**: Har ek tukde (part) ka size 5 MB se lekar 5 GB ke beech hona chahiye (Sirf aakhri part ka size 5 MB se kam ho sakta hai).
- **Max Parts**: Aap ek file ko maximum 10,000 parts mein tod sakte hain.

### Multi-part Upload Kaam Kaise Karta Hai?

Maan lijiye aapke paas ek 4 GB ki video file (```movie.mp4```) hai aur aap ise S3 par upload karna chahte hain. Multi-part upload ise 3 main steps mein handle karega:

**Step 1: Initiate Upload (Shuruat)**:

Aapka application S3 ko ek request bhejta hai: "Main ek badi file upload karna chahta hoon". S3 badle mein aapko ek unique Upload ID deta hai. Ye ID ek token ki tarah kaam karti hai jo aapke saare aane wale tukdon (parts) ko aapas mein jode rakhegi.

**Step 2: Upload Parts (Tukdon ko bhejna)**:

Aapka application uss 4 GB ki file ko 1-1 GB ke 4 parts mein tod deta hai.
```
Part 1 (1 GB) -> Uploaded with Upload ID
Part 2 (1 GB) -> Uploaded with Upload ID
Part 3 (1 GB) -> Uploaded with Upload ID
Part 4 (1 GB) -> Uploaded with Upload ID
```
Har part ke sath aapko Upload ID aur ek Part Number (jaise 1, 2, 3...) bhejna hota hai.

Jab ek part successfully upload ho jata hai, toh S3 response mein ek **ETag** (ek unique hash code/checksum) deta hai. Aapke application ko yeh ETag aur Part Number apne paas note karke rakhna hota hai.

**Step 3: Complete Upload**:

Jab saare parts upload ho jaate hain, to aapka application S3 ko ek final "Complete" request bhejta hai jismein saari Part Numbers aur unki ETags ki list hoti hai. S3 is list ko check karta hai, saare parts ko sahi sequence (1, 2, 3...) mein jodta hai, aur aapki ek final file bucket mein save ho jaati hai.

### S3 Multipart Upload Ki Ek Badi Problem aur Uska Solution

**Problem: S3 Ka Hidden Cost (Incomplete Multipart Uploads)**:

Maan lijiye aapne ek 50 GB ki file ka upload shuru kiya. 30 GB upload hone ke baad aapka network chala gaya ya aapne script band kar di. Ab yeh 30 GB data S3 ke backend mein store rahega, par aapko bucket mein koi file dikhayi nahi degi kyunki upload Complete nahi hua. Yeh adha-adhura data aapko dikhega nahi, par AWS iska storage cost (bill) aapse leta rahega.

**Solution: S3 Lifecycle Policy**:

Is paise ki barbadi ko rokne ke liye hamesha S3 par ek Lifecycle Rule set kiya jata hai jise kehte hain: ```"AbortIncompleteMultipartUpload"```.

Aap rule set kar sakte hain ki agar koi multi-part upload 7 din ke andar "Complete" nahi hota, to S3 uske saare temporary parts ko automatically delete kar de taaki aapka faltu bill na bane.

### Multi-part Upload Ke Fayde (Benefits)

**Behtar Speed (Parallel Uploading)**: Agar aap ek single 4 GB ki file bhejenge, to wo ek single connection se jayegi. Multi-part mein aap dono-teeno parts ko ek saath (parallelly) bhej sakte hain, jisse aapke internet ki poori bandwidth use hoti hai aur upload bohot fast ho jata hai.

**Network Fault Tolerance (Quick Recovery)**: Maan lijiye aap single file upload kar rahe the aur 95% par internet disconnect ho gaya. Aapko poori file shuru se upload karni padegi. Lekin Multi-part mein agar Part 3 fail hua, to sirf Part 3 hi dobara upload karna padega, baaki ke safe parts S3 ke paas waise hi rahenge.

**Pause aur Resume**: Aap upload ko beech mein rok (pause) sakte hain aur bache hue parts ko baad mein bhej kar resume kar sakte hain.

### Kya Yeh Hamein Code Se Manually Karna Padta Hai?

Agar aap **AWS CLI** ya **AWS SDK** (jaise Python mein ```boto3```) use kar rahe hain, to aapko ye steps manually likhne ki zaroorat nahi hoti.

**AWS CLI**: Jab aap ```aws s3 cp movie.mp4 s3://my-bucket/``` command chalate hain, to AWS CLI background mein file ka size check karta hai. Agar file badi hai, to wo apne aap multi-part upload shuru kar deta hai.
- CLI mein default limit 8 MB hoti hai.
- Jab aap ```aws s3 cp``` ya ```aws s3 sync``` chalate hain aur file ka size 8 MB se zyada hota hai, to CLI automatically background mein multi-part upload perform karta hai.

<br>

**AWS SDKs (Python Boto3, Node.js, Java, etc.)**:
- High-Level Methods (Automatic): Agar aap built-in high-level functions use kar rahe hain (jaise Python Boto3 mein ```upload_file()``` ya ```boto3.s3.transfer```), to SDK automatically file size detect karke multi-part chunks bana deta hai. Aapko manually kuch nahi karna padta.
- Low-Level API (Manual): Agar aap S3 ki core low-level API call kar rahe hain (jaise ```put_object```), to multi-part automatic kaam nahi karega. Wahan aapko manually teen APIs call karni padengi: ```create_multipart_upload```, ```upload_part```, ```aur complete_multipart_upload```.

### Agar hum console pe jaake upload button se file upload kar rahe hain to kya tab bhi multi part upload work karega?

**Haan**, agar aap AWS Console par jaakar Upload button se file upload karte hain, to tab bhi Multi-part Upload automatically kaam karta hai.

AWS Console itna smart hai ki jab aap koi badi file drag-and-drop karte hain ya select karte hain, to browser-level par hi wo file chhote-chhote parts mein divide ho jaati hai aur background mein Multi-part Upload shuru ho jata hai. Aapne notice kiya hoga ki jab aap console se badi file upload karte hain, to ek progress bar dikhta hai jo kaafi tezi se aage badhta hai—wo parallel uploading ki wajah se hi hota hai.

**AWS Console Mein Yeh Kab Work Karta Hai?**

AWS Console mein multi-part upload ka ek threshold set hota hai:
- **Small Files (< 160 MB**): Agar aapki file ka size 160 MB se kam hai, to console use ek single piece (Single-part standard upload) mein bhejta hai.
- **Large Files (> 160 MB)**: Agar file 160 MB se badi hai, to console automatically code run karke use multi-part mein convert kar deta hai.
- **Maximum Limit**: Console ke zariye aap maximum 160 GB tak ki file upload kar sakte hain (kyunki browser ki local memory aur timeout limits hoti hain). Agar aapko 160 GB se badi file bhejni hai (S3 ki max limit 5 TB tak), to aapko AWS CLI ya SDK use karna padega.
