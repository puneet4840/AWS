# IAM Policies (User Level Security)

Ab hum S3 Security ke ek bahut important part par aate hain: **IAM Policies**, jise tum is context mein broadly user-level security bhi samajh sakte ho.

Is concept ko samajhna bahut important hai, kyunki S3 bucket secure karne ka matlab sirf bucket ko private bana dena nahi hota. Humein ye bhi decide karna hota hai ki kaunsa IAM user, IAM role, ya application S3 mein exactly kya kar sakta hai.

For example:
- Kaunsa user bucket dekh sakta hai?
- Kaunsa user files upload kar sakta hai?
- Kaunsa user files download kar sakta hai?
- Kaunsa user files delete kar sakta hai?
- Kaunsa user bucket create ya delete kar sakta hai?
- Kya user poori bucket access kar sakta hai ya sirf ek specific folder/prefix?
- Kya EC2 instance S3 access kar sakta hai?
- Kya developer sirf logs upload kar sakta hai lekin unhe delete nahi kar sakta?

In sab permissions ko control karne ke liye **IAM policies** use hoti hain.

<br>

IAM Policies (User Level Security) ka matlab hota hai ki hum User, Group ya Role ko AWS ke IAM service mein jake access provide karte hai. Isme hum S3 ki permissions dete hain, jisse User, Groups ya Role AWS console mein S3 service ko access kar sakta hai.

<br>
<br>

### Sabse pehle IAM Policy kya hoti hai (S3 ke context mein)?

IAM Policy ek JSON document hoti hai jisme hum AWS ko batate hain ki:
- Kaun sa principal(User, Group, Role), AWS ke S3 resource par, kaunsa action perform kar sakta hai, aur kis condition ke under perform kar sakta hai.

IAM policy ka matlab hai ki konsa User, Group ya Role, S3 bucket par konsa action perform kar sakta hai.

<br>

Is definition ko thoda todkar samajhte hain

Ek permission request mein generally kuch important cheezein hoti hain:

**Principal**:

Kaun request kar raha hai?

Example:
- IAM User.
- IAM Role.
- AWS service.
- Federated user.

**Action**:

Wo kya karna chahta hai?

Example:
- s3:GetObject
- s3:PutObject
- s3:DeleteObject
- s3:ListBucket

**Resource**

Wo kis resource par action perform karna chahta hai? Ya konse S3 bucket par action perform karna chta hai?

Example:
```
arn:aws:s3:::my-bucket
```
ya:
```
arn:aws:s3:::my-bucket/*
```

**Effect**:

Permission allow karni hai ya deny?
```
"Effect": "Allow"
```
ya:
```
"Effect": "Deny"
```

**Condition**

Permission kis special condition ke under allowed ya denied hogi?

Example:
- Sirf specific IP address se access.
- Sirf MFA ke saath delete permission.
- Sirf encrypted connection ke through access.
- Sirf specific AWS Region ya account context mein access.

### S3 Security mein IAM Policy kya role play karti hai?

Maan lo AWS Account ke andar tumhare paas ek S3 Bucket hai.
```
company-data-bucket
```

Is bucket ke andar objects hain.
```
company-data-bucket
│
├── employees.csv
├── salary.xlsx
├── application-logs/
│
│   ├── app-1.log
│   └── app-2.log
│
└── public-assets/
    ├── logo.png
    └── banner.jpg
```

Ab company mein multiple IAM Users hain.
```
Puneet
Amit
Rahul
Developer-Team (Group)
```

Ab tum nahi chahoge ki sabhi users bucket ke andar sab kuch access kar saken.

For example:
- ho sakta hai Puneet ko sirf application logs dekhne ki permission chahiye.
- Amit ko objects upload karne ki permission chahiye.
- Rahul ko sirf bucket ke kuch specific objects read karne ki permission chahiye.
- Aur kisi normal developer ko salary.xlsx access nahi milni chahiye.

Isi ko manage karne ke liye **IAM Policy** ka role aata hai.
