# LAB: S3 Versioning Hands-on Lab

Chaliye, S3 Versioning ka ek complete production-level master lab karte hain. Is single lab mein hum real-world IT companies ke sabhi major scenarios ko cover karenge.

Is lab ko poora karne ke baad aapko samajh aa jayega ki kaise S3 versioning ransomware attacks, developers ki galti aur data recovery ko handle karti hai.

<br>
<br>

### Lab Objective & Scenarios

Hum apni ```meri-bucket-puneet``` ka use karenge aur ye 4 Scenarios live test karenge:
- Scenario 1 (Application Code Overwrite): Ek hi file ke multiple updates/versions ko track karna.
- Scenario 2 (Accidental Delete): Kisi file ko galti se normal delete karna aur use vapas laana.
- Scenario 3 (Permanent Delete/Purge): Kisi purane bekaar version ko hamesha ke liye mitaana.
- Scenario 4 (Ransomware/Malicious Delete): Pure folder ke delete hone par pure data ko ek sath recover karna.

<br>

**Prerequisites**:

Apne computer par ek folder banayein aur usme do dummy notepad files banayein:
- **File 1**: Naam rakhein ```index.html```. Uske andar likhein: ```<h1>Version 1: Old Website</h1>```.
- **File 2**: Ek aur file banayein, naam wahi rakhein ```index.html```. Par andar ka text badal dein: ```<h1>Version 2: New Website</h1>```.

<br>
<br>

### Step 1: Bucket Mein Versioning ON Karein

- AWS Console mein **S3** open karein aur apni bucket ```meri-bucket-puneet``` par click karein.
- **Properties** tab mein jayein.
- **Bucket Versioning** section mein **Edit** par click karke use **Enable** karein aur **Save changes** kar dein.

<br>
<br>

### Scenario 1: File Overwrite Aur State Tracking (Code Update)

Real-world situation: Ek developer ne naya website ka code upload kiya, par usme bug (error) nikal aaya. Ab hume pichle working code par roll-back (wapas) jana hai.

- Bucket ke **Objects** tab mein jayein aur **Upload** par click karein.
- Apne computer se **File 1** (Version 1 wali ```index.html```) ko upload kar dein.
- Upload complete hone ke baad, wapas bucket mein aayein aur usi same jagah par **File 2** (Version 2 wali ```index.html```) ko upload kar dein.
- **Result**: Bucket ke normal view mein aapko sirf ek hi ``index.html``` dikhegi (jo ki Version 2 hai).
- **How to see history?** Bucket ke andar top right mein diye gaye **Show versions** wale toggle switch ko **ON** kariye.
- **Observation**: Ab aapko do files dikhenge:
  - Jo sabse upar hai, wo **Latest version** hai (Version 2).
  - Jo uske niche hai, wo **Old version** hai (Version 1). Dono ki unique Version ID hogi (jaise ```g3xK9...```).

**Rollback Kaise Karein?** Agar aapko purani website ka data chahiye, toh aap niche wale (purane) version ko select karke direct Download ya Open kar sakte hain. Aapka purana data 100% safe hai!

### Scenario 2: Accidental Delete

Real-world situation: Ek naye employee ne galti se live production file ko select kiya aur delete button daba diya.

- Show versions switch ko **OFF** kar dein (taaki normal view dikhe).
- ```index.html``` file ko select karein aur upar se **Delete** button daba dein.
- AWS aapse confirmation maangega. Box mein ```delete``` type karein aur **Delete objects** par click kar dein.
- **Observation**: Bucket ab bilkul khali dikhegi. Ek normal user sochega ki data hamesha ke liye chala gaya.
- **Recovery Process**: Phir se **Show versions** switch ko **ON** kariye.
- Aap dekhenge ki aapki dono purani ```index.html``` files abhi bhi wahan maujood hain! Unke sabse upar AWS ne ek naya version joda hai jise kehte hain **Delete Marker** (Type: Delete marker).
- **Fix**: Us Delete Marker wali single row ko select karein, upar se **Delete** button dabayein, aur confirm karne ke liye is baar box mein ```permanently delete``` type karke enter karein.
- Jaise hi Delete Marker permanent delete hoga, Show versions ko **OFF** karke dekhiye—aapki original file bina kisi data loss ke apni jagah wapas aa chuki hai!

<br>
<br>

### Scenario 3: Permanent Delete / Space Saving (Purge)

Real-world situation: Aapki storage full ho rahi hai aur aapko pata hai ki 6 mahine purana jo version 1 tha, wo ab bilkul bekaar hai aur use hamesha ke liye mitana hai taaki bill kam aaye.

- Show versions switch ko **ON** karein.
- Aapko jo sabse niche wala **purana version** (Version 1) dikh raha hai, sirf uske samne wale checkbox par tick lagayein. (Latest version par tick mat lagana).
- Upar se **Delete** button par click karein.
- Kyunki aap ek specific version ID ko delete kar rahe hain, AWS aapse confirm karne ke liye kahega. Box mein ```permanently delete``` type karein aur delete daba dein.
- **Observation**: Ab aapka purana version hamesha ke liye cloud se mit chuka hai, use AWS ka owner bhi wapas nahi la sakta. Lekin aapka latest version abhi bhi chal raha hai.

<br>
<br>

### Scenario 4: Ransomware Attack / Bulk Cyber Attack

Real-world situation: Kisi hacker ne aapke account ka access le liya ya kisi script ne galti se pure folder ke andar ki 50-60 files ko ek sath delete kar diya.

- Man lijiye aapki bucket mein aisi hi kafi files hain aur sab ek sath delete ho gayin (Normal view khali hai).
- **Bulk Recovery Kaise Karein?**:
  - **Show versions** ko **ON** karein.
  - Aapko har file ke upar ek-ek ```Delete Marker``` dikhayi dega.
  - Aap upar diye gaye master checkbox par tick lagakar saare **Delete Markers ko ek sath selec**t kar lijiye. (Dhyan rahe, sirf delete markers ko select karna hai, asli versions ko nahi).
  - Upar se **Delete** button dabayein aur ```permanently delete``` likh kar confirm kar dein.
  - Jaise hi saare folders aur files ke delete markers ek sath saaf honge, aapka poora ka poora database ya folder structure 1 second mein wapas apni purani sahi-salamat state mein aa jayega.
