# MFA Delete

Pichle slide meinn humne dekha Bucket Versioning, jisme bucket mein ek object ke multiple versions ko store kar rahe the. 

Suppose ek bucket hai usme versioning on hai aur usme kuch objects stored hain. Ab koi user, jiske paas elevated permissions hain to vo bucket ke ander stored objects ko aur unke versions ko delete kar sakta hai aur bucket verioning ki state ko change kar sakta hai. Jo ki ek security threat hai.

Isi chiz se bachne ke liye MFA Delete ka use kiya jata hai. MFA Delete kya karta hai, Agar kisi bucket par MFA Delete option On hai to, agar user bucket ke objects aur uske versions ko delete ya fir bucket versioning ki state ko change karne ki koshish karega to usko additional OTP chaiye hoga delete karne ke liye. Yehi MFA Delete hota hai.

<br>
<br>

### MFA Delete Kya hai?

Amazon S3 **MFA Delete** ek security feature hai jo version-enabled S3 bucket mein additional authentication factor require karta hai jab kisi object version ko permanently delete karna ho ya bucket ki Versioning state change karni ho.

MFA Delete sirf unhi buckets par apply hota hai jisme bucket versioning enabled ho. 

Ye simply ek security feature hai jo bucket ke ander versions ya bucket state change karne ke liye ek extra authentication chiaye hoti hai, jaise ki apki device ke uper ek OTP, Jab aap delete karte time vo OTP de doge to, aap MFA Delete kar sakte ho.

Normal Versioning mein:
```
S3 Bucket
    │
    ├── Version 1
    ├── Version 2
    └── Version 3
```

Agar kisi authorized principal ke paas appropriate permission hai, to specific version ko permanently delete kiya ja sakta hai.

MFA Delete enable karne ke baad:
```
Permanent Version Delete
        │
        ▼
AWS credentials
        +
MFA code
        │
        ▼
Delete allowed
```
Yaani sirf credentials hona enough nahi hota; MFA Delete ke protected operations ke liye additional MFA authentication required hoti hai.

<br>
<br>

### MFA Delete ki zarurat kyun hai?

Maan lijiye aapki company ka ek S3 bucket hai jisme aapne Versioning ON kar rakhi hai. Aap sukoon se baithe hain ki agar koi file delete bhi ho gayi, to versioning se wapas aa jayegi.

Lekin sochiye agar:
- Kisi hacker ko aapke ek IAM User (Admin) ke AWS Access Keys mil gaye.
- Ya fir company ka koi purana employee gusse mein aakar saara data mita dena chahta hai.

Wo hacker S3 console ya CLI par jayega, ```"Show Versions"``` par click karega, saare versions ko select karega aur Permanently Delete kar dega. Is case mein AWS Versioning bhi aapko nahi bacha sakti kyunki asli versions hi delete ho chuke hain.

Yahan entry hoti hai MFA Delete ki. Agar yeh feature ON hai, to hacker ke paas Admin access hone ke baad bhi AWS use data permanent delete nahi karne dega jab tak wo live MFA token nahi dalta.

<br>

Suppose production bucket hai:
```
production-data
```
Aur is bucket par Versioning enabled hai.

Bucket ke ander ye Object hai:
```
database-backup.sql
```

Aur saath hi object ke versions stored hain:
```
Version 1
Version 2
Version 3
Version 4
```
Ab Version 4 current hai.

Suppose kisi attacker ke paas administrator ke credentials aa gaye. Matlab admin ke creadentials leak ho gaye.

Attacker ke paas saari permissions bhi aa jayengi, vo admin ke credentials ka use karke AWS mein kuch bhi kar sakta hai. Ab attacker ke paas version delete karne ki required permissions hain.

Without MFA Delete, attacker specific versions ko permanently delete karne ki koshish kar sakta hai.
```
Attacker
   │
   ▼
Compromised Credentials (Admin)
   │
   ▼
Delete Version
   │
   ▼
Version permanently deleted
```
Versioning enabled hone ke baad bhi historical versions ko permanently delete karna possible ho sakta hai, depending on permissions.

MFA Delete additional barrier create karta hai:
```
Attacker
   │
   ▼
Compromised Credentials
   │
   ▼
Delete Version
   │
   ▼
MFA required
   │
   ▼
Attacker doesn't possess MFA device
   │
   ▼
Request fails
```
Agar attacker versions ko delete karne ki koshish karega to usko delete karne ke liye additional authentication chaiye hoga, jo attacker ke paas hoga nhi, sirf admin ke mobile device par hoga. To is case mein attacker versions ko delete nahi kar payega.

Isi wajah se MFA Delete accidental ya unauthorized permanent deletion ke against additional protection provide karta hai. AWS specifically compromised credentials scenario mein is additional protection ko highlight karta hai.

<br>
<br>

### MFA Delete kis operation ko protect karta hai?

MFA Delete pure bucket par har samay kaam nahi karta. Yeh sirf do specific high-risk operations par rok lagata hai:
- Permanently Deleting an Object Version.
- Changing Bucket Versioning State.

**Permanently Deleting an Object Version**: Jab aap versioning-enabled bucket mein se kisi file ke ek specific Version ID ko permanently delete karne ki koshish karte hain, to bina MFA ke request fail ho jayegi.

Example:
```
report.pdf
Version ID = abc123
```
Agar tum:
```
Delete version abc123
```
karna chahte ho, MFA required ho sakti hai.

<br>

**Changing Bucket Versioning State**: Agar koi aapke bucket ki versioning ko Suspend (band) karne ki koshish karega, to use MFA code dena padega. (Kyunki hacker pehle versioning band karte hain, fir file delete karte hain).

Note: Agar aap bina Version ID bataye normal delete (```s3:DeleteObject```) karte hain, jisse sirf ek Delete Marker banta hai, to uske liye MFA ki zaroorat nahi hoti. Kyunki usse data sach mein delete nahi ho raha, sirf chhup raha hai.

<br>
<br>

### MFA Delete Ke Strict Rules (Prerequisites)

MFA Delete ko configure karne aur use karne ke AWS ne bohot hi strict rules banaye hain, jinhe dhyan se samajhna zaroori hai:

- **Sirf Root Account Hi ON/OFF Kar Sakta Hai**: Aapka IAM User chahe jitna bada Admin ho (AdministratorAccess), wo MFA Delete ko ON ya OFF nahi kar sakta. Yeh power sirf aur sirf AWS Root Account (jis email se AWS account bana tha) ke paas hoti hai.

- **AWS Console Se ON Nahi Hota**: Aap AWS Console (browser) mein jaakar kisi button ko click karke ise ON nahi kar sakte. Isko enable karne ke liye aapko AWS CLI (Command Line Interface) ya API ka hi use karna padta hai.

- **Hardware ya Virtual MFA Devie Required**: Root account ke sath ek MFA device (jaise Google Authenticator, Authy, ya koi hardware token) link hona compulsory hai. Matlab root account par MFA setup hona jaruri hai tabhi MFA delete option enable kar sakte ho.

<br>
<br>

### MFA Delete Kaise ON Kiya Jata Hai?

MFA Delete ko aap AWS Console(UI) se **ON** nahi kar sakte. AWS ne isko janbujhkar thoda mushkil banaya hai taaki koi galti se ya unauthorized tarike se ise change na kar sake.

Isko on karne ke liye AWS CLI mein ek specific command chalani padti hai. Iska tareeka neeche diye gaye steps jaisa hota hai:

Ise ON karne ke liye sirf do cheezein zaroori hain:
- Aapko AWS Account ke Root User (Main Account) ke credentials se login karna hoga. Kisi bhi IAM User ya Admin ke paas iski permission nahi hoti.
- Aapko AWS CLI (Command Line Interace) ka use karna padega.

**Step 1**: Pehle aapko apne Root Account ke liye AWS CLI configured rakhna hoga.

**Step 2**: Aapko apne MFA device ka Serial Number (ARN) chahiye hoga (jo AWS IAM console mein Root user ke security credentials mein dikhta hai).

**Step 3**: Aap CLI par yeh command chalate hain:
```
aws s3api put-bucket-versioning \
    --bucket my-highly-secure-bank-bucket \
    --versioning-configuration Status=Enabled,MFADelete=Enabled \
    --mfa "arn:aws:iam::123456789012:mfa/root-user-device 999888"
```
- ```--bucket```: Aapke secure bucket ka naam.
- ```--versioning-configuration```: Yahan hum ```MFADelete=Enabled``` set kar rahe hain.
- ```--mfa```: Isme aapke Root account ke MFA device ka **ARN** path hota hai aur aakhiri mein space dekar us samay ka 6-digit live MFA Code (**999888**) likhna hota hai.

<br>
<br>

### MFA Delete Active Hone Ke Baad File Delete Kaise Hoti Hai?

MFA Delete ON hone ke baad agar aapko koi file permanently delete karni hai, toh process kuch aisa dikhega:

```
[User runs Deletion Request] 
            |
            v
   (Does it have MFA Code?) 
      /              \
    ❌ No            icon:check_green Yes
    /                  \
[Access Denied 403]   [Object Permanently Deleted]
```

- **The Request**: Ek developer ne CLI se command chalayi kisi version ko delete karne ke liye: ```aws s3api delete-object --bucket secure-bucket --key file.txt --version-id v11111```.
- **The Reject**: AWS turant check karega ki kya request mein ```--mfa``` parameter aur live OTP shamil hai? Agar developer ne sirf normal command chalayi hai, toh AWS use 403 Forbidden (Access Denied) error de dega, chahe woh khud user hi kyun na ho.
- **The Approval**: Data tabhi delete hoga jab command mein physical device ka live OTP pass kiya jayega:
```
aws s3api delete-object --bucket secure-bucket --key file.txt --version-id v11111 --mfa "arn:aws:iam::... 123456"
```

### Questions

### Question:1 - Kya MFA Delete sirf AWS CLI ke through hi Enable aur Disable kiya ja sakta hai?

**Jawaab: HAAN**.

AWS Management Console (yaani jo browser mein aap AWS ki website kholte hain) mein MFA Delete ko ON ya OFF karne ka koi button ya option hota hi nahi hai.

- **Kyun aisa hai?** AWS ne ise jaanbujhkar aisa banaya hai (Security by Design). Agar koi hacker aapke browser ka session compromise kar le (ya aap computer khola chhodkar chale jayein), to wo aasani se click karke ise band na kar sake.
- **Akela Tarika**: Ise enable ya disable karne ka akela tarika AWS CLI ya AWS SDK/API (jaise Python ki Boto3 library) hi hai.
- **Akela Use**r: Aur jaisa humne pehle baat ki, CLI use karte waat bhi aapko AWS Root Account ki Access Keys lagengi. Ek normal IAM Admin user CLI se bhi ise ON/OFF nahi kar sakta.

<br>

### Question:2 - Agar bucket mein MFA Delete ON hai, aur hum Console (Browser) se file ya uske versions ko delete karein, to kya hoga? Kya console par MFA maangega?

Iska jawaab bohot dilchasp hai. Isko samajhne ke liye hume do alag-alag delete operations ko dekhna padega jo aap console se karte hain:

**Case A: Console se "Normal Delete" karna (Bina "Show Versions" ON kiye)**:

Maan lijiye aapne S3 Console khola, aapko ```file.txt``` dikhi, aapne use select kiya aur "Delete" par click kar diya.

Kya MFA maangega? Answer hai NAHI.

Kyun? Kyunki normal delete karne se AWS backend mein sirf ek Delete Marker (0 KB ka parda) lagata hai. Aapka asli data delete nahi ho raha hai, wo piche safe hai. Kyunki isse data ka nuksan nahi ho raha, isliye S3 Console aapse bina koi MFA maange file ko samne se gayab kar dega.

<br>

**Case B: Console se "Permanent Delete" karna ("Show Versions" ON karke)**:

Maan lijiye aapne Console par upar "Show Versions" ka toggle switch ON kiya. Ab aapko ```file.txt``` ke saare versions (ID: 111, ID: 222) dikhne lage. Aapne kisi ek version ko ya fir Delete Marker ko select kiya aur "Delete" par click kiya.
- S3 Console Ka Behavior: AWS S3 Console ka internal architecture is tarah design kiya gaya hai ki S3 Console ke paas delete karte waqt MFA Token (OTP) accept karne ka koi text box ya input field hota hi nahi hai.
- Result kya hoga? Jaise hi aap Console par "Permanently Delete" confirm karke button dabayenge, AWS backend check karega ki is bucket par to MFA Delete ON hai. Kyunki console ne request ke sath MFA code nahi bheja (kyunki wahan option hi nahi tha), AWS backend console ki request ko block kar dega aur aapko screen par ek bada sa Access Denied (Failed to delete object) ka error message de dega.

<br>

**Conclusion**:

MFA Delete sirf CLI se hi enable/disable hota hai. Aur agar aapko kisi version ko permanent delete karna hai, to wo kaam bhi sirf aur sirf CLI ya API ke through hi ho sakta hai. Console se MFA Delete nhi ho sakta.

MFA Delete lagne ke baad S3 Console poori tarah se "Read-Only" ban jata hai permanent deletion ke mamle mein. Agar koi hacker console mein ghus bhi jaye, wo chah kar bhi console se aapke kisi version ko delete nahi kar payega kyunki console par MFA code dalne ki jagah hi nahi hai, aur bina code ke AWS backend use reject kar dega.
